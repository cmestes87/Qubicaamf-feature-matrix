# QubicaAMF Feature Matrix

A single-page sales reference tool comparing feature availability across:

- **BES NV** vs **BES NV Value**
- **Neoverse Interactive Edition** vs **Neoverse Standalone**

Each product view shows a subscription toggle (dims + marks features that are
lost if the subscription lapses) and flags **Neo-Fi** content that requires
both BES NV and Neoverse Interactive Edition together.

`index.html` at the repo root is the entire deployable app — no build step
needed to host it, no server, no dependencies. It's what GitHub Pages serves.

## Live site

Once GitHub Pages is enabled (Settings → Pages → Source: `main` branch, `/` root),
it will be live at:

```
https://<your-github-username>.github.io/qubicaamf-feature-matrix/
```

## Updating the data

When the feature/subscription/Neo-Fi data changes:

1. Replace the relevant file(s) in `source/spreadsheets/`:
   - `Neoverse_for_Claude.xlsx`
   - `BES_NV_Environments_and_Features_for_Claude.xlsx`

   Keep the same sheet/column layout as the existing files — the extractor
   expects:
   - Neoverse workbook, first sheet: `Name | Neoverse Interactive Edition | Neoverse (Stand Alone) | Requires Subscription | Requires BES NV`, with category-header rows (name only, other columns blank) separating sections.
   - BES NV workbook, sheet named `Sheet2`: `Environments | BES NV | Requires Subscription | BES NV Value | Requires Subscription | Neo-Fi`, with the same category-header-row convention.

2. Regenerate `source/data.json`:
   ```bash
   cd source
   python3 extract.py
   ```

3. Rebuild `index.html`:
   ```bash
   python3 build.py
   ```

4. Commit and push:
   ```bash
   git add .
   git commit -m "Update feature data"
   git push
   ```

GitHub Pages redeploys automatically, usually within a minute or two.

## Editing the design or behavior

Edit `source/template.html` (this is the actual HTML/CSS/JS — it contains
`__DATA_JSON__` and `__BADGE_B64__` placeholders that `build.py` fills in).
After editing, just run:

```bash
cd source
python3 build.py
```

## Requirements

Python 3 with `openpyxl` installed:

```bash
pip install openpyxl
```

(Only needed for `extract.py` — `build.py` has no dependencies beyond the
standard library.)

## Repo layout

```
index.html                  <- deployable app (GitHub Pages serves this)
source/
  template.html              <- HTML/CSS/JS source with placeholders
  data.json                  <- extracted feature data (regenerated by extract.py)
  extract.py                 <- spreadsheets -> data.json
  build.py                   <- template + data.json + badge -> ../index.html
  spreadsheets/               <- source-of-truth spreadsheets
  assets/                      <- QubicaAMF badge (image + base64)
```
